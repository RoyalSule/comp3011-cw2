# COMP3011 Coursework 2 – Web Search Engine

A command-line search engine that crawls [quotes.toscrape.com](https://quotes.toscrape.com/), builds an inverted index, and lets you query it interactively.

---

## Project Overview

The tool is split into three independent modules:

| Module | Responsibility |
|--------|----------------|
| `src/crawler.py` | Fetches all pages reachable from the base URL; respects a 6-second politeness window |
| `src/indexer.py` | Builds an inverted index (`word → {url → {frequency, positions}}`); serialises to/from JSON |
| `src/search.py` | Wraps the index with `print` and `find` query operations |
| `src/main.py` | Interactive command-line shell |

## Usage

Start the interactive shell from the `src/` directory:

```bash
cd src
python main.py
```

### Commands

#### `build`
Crawls the website, builds the inverted index, and saves it to `data/index.json`.

```
> build
```

> **Note:** The crawler respects a 6-second politeness window between requests. A full crawl of quotes.toscrape.com takes approximately 5–10 minutes.

---

#### `load`
Loads a previously saved index from `data/index.json`. Only needs to be run once after `build` — use this for all subsequent sessions.

```
> load
```

---

#### `print <word>`
Displays the inverted index entry for a single word, showing every page it appears on, its frequency, and token positions.

```
> print world
> print indifference
```

**Example output:**
```
Results for 'world' (2 page(s)):

  URL       : https://quotes.toscrape.com/
  Frequency : 3
  Positions : [4, 22, 87]

  URL       : https://quotes.toscrape.com/page/2/
  Frequency : 1
  Positions : [11]
```

---

#### `find <term(s)>`
Returns all pages containing **every** term in the query (AND logic). Works for single and multi-word queries.

```
> find indifference
> find good friends
> find life choices world
```

**Example output:**
```
Pages containing 'good' + 'friends':
  https://quotes.toscrape.com/page/3/
  https://quotes.toscrape.com/page/7/
```

---

#### `help`
Prints a command reference.

---

#### `quit` / `exit`
Exits the shell.

## Testing

Run the full test suite with coverage from the repository root:

```bash
pytest tests/ -v --cov=src --cov-report=term-missing
```

Run a specific test file:

```bash
pytest tests/test_indexer.py -v
```

### Test structure

| File | What it tests |
|------|--------------|
| `tests/test_crawler.py` | URL normalisation, domain filtering, link extraction, HTTP error handling, politeness window |
| `tests/test_indexer.py` | Tokenisation, punctuation stripping, script/style exclusion, index building, save/load round-trip |
| `tests/test_search.py` | Single-word queries, multi-word AND logic, edge cases (empty query, missing words, duplicates) |

## Design Decisions

### Inverted Index Structure

```json
{
  "word": {
    "https://example.com/page1": {
      "frequency": 3,
      "positions": [5, 12, 45]
    }
  }
}
```

- **Nested dict** chosen over a flat list for O(1) URL lookups.
- Storing **positions** (not just frequency) enables future phrase/proximity search.
- **JSON serialisation** keeps the format human-readable and requires no external database.

### Search Logic

Multi-word `find` queries use **set intersection**: pages for each term are collected as Python sets, then intersected. This is efficient and scales linearly with the number of terms.

### Case Insensitivity

All tokens are lower-cased at index time; query terms are also lower-cased before lookup, so the index stays compact and searches are always case-insensitive.
